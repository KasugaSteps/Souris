# Souris v0.1 产品说明书

> 范围：Qwen3.8-Flash-Next，SRS1 v1，GGML，无 libllama。
>
> 本文件只定义 v0.1 产品约束。旧开发/测试权重格式不再支持。

---

# 0. 目标与非目标

**目标**

```text
1. Prompt 128–32768 可跑通。
2. Decode 可连续生成。
3. Prefill layer-major，每层 expert union 只读一次。
4. hidden 在 Prefill 期间驻留 GPU，Prefill 后归还。
5. Prefill MoE 走 GGML MMQ + fused SwiGLU/Q8_1 epilogue。
6. Decode 与 MTP verify 共用 NativeLayerKernels<MAX_T>。
7. C++ 常驻 raw completions server；ExpertCache 跨请求保留。
8. 可选 MTP speculative Decode，最多 4 个 draft。
9. CLI 提供 raw 交互式 chat；Python frontend 完整支持 OpenAI/pi-mono。
10. SRS1 v1 支持 GGML 2/3/4bit 量化类型。
11. 所有量化级别预留接口；v0.1 只验证 IQ2_XXS 目标权重。
12. 支持单请求多张离散静态图片（最多 4 张）：每张固定 768×768、576 image tokens，由 mmproj vision encoder 编码后注入文本模型。
13. 支持 tool-call 采样约束：固定 JSON tool-call 格式，tool name 为 enum，arguments 按可编译 JSON Schema 子集做 grammar mask。
14. Tool-call 目标不是“只通过语法”，而是 Pi 在 tool_choice=auto 下完成读取 PROMPT_EN、连续调用工具、写文件、跑测试的完整 agent 循环。
```

**非目标**

```text
continuous batching
KV host offload
paged KV
KV streaming
MTP 训练
MTP 多 GPU
CPU expert 计算
多 GPU
page cache 作为正式缓存层
Prefill CUDA Graph
旧 SRS1 v3 / SRT3 兼容
固定 record_bytes
固定 D_total
图片生成
video/audio
GIF/APNG/animated WebP
动态图片分辨率
image crop/stretch（只允许 letterbox pad）
repetition_penalty / presence_penalty / frequency_penalty
```

# 1. 硬约束

```text
1. 所有 expert 计算在 GPU。
2. Expert 文件读取使用 O_DIRECT，不依赖 page cache。
3. Prefill 外层按 layer，chunk 只做 token tile。
4. Prefill 每层 expert union 只读一次。
5. hidden 只保存一份，Prefill 期间借用 SlotPool 尾部，结束后归还。
6. route ids/rows/dst 留在 GPU。
7. host 只允许 Prefill counts[512]；Decode counts/miss_keys/hit_slots 和最终 token。
8. Prefill target MoE 使用 Q8_1 activation、GGML MMQ、int8 tensor core、FP32 累加。
9. Prefill gate/up 一个 Product，down 一个 Product；禁止 per-bit dequant kernel。
10. mmq_group 可调，建议 8–32，默认 16，实验上限 64；禁止 per-expert launch。
11. Prefill MoE 不新增模块或接口；仍由 MoEKernel 承担，MMQ 是内部实现。
12. Decode/MTP verify 使用 Q8_1 native MMVQ；MTP draft 使用 Q4_0。
13. KV 只使用 Q8_0，全 GPU，append-only。
14. 每层 activation 只量化一次；同一组 projection 共用 Q8_1 scratch。
15. Decode/MTP pre/post 必须按 (layer, quant_signature, MAX_T) 预建 graph。
16. 禁止 Decode 与 MTP verify 各维护一套 pre/post kernel。
17. Decode/MTP 只保留 NativeLayerKernels 一条执行路径。
18. record_bytes 由 header role layout 动态派生，不得写死。
19. D_total 必须用 layout.record_bytes 计算。
20. SlotPool / ExpertCache / StagingRing / TransferEngine / MMQ 必须使用同一个 Layout。
21. Python frontend 完整支持 OpenAI/pi-mono；C++ 只做 raw completion。
22. timeout、retry、idempotency、cancel 由 Python frontend 负责，C++ 不重试。
23. stream 开始后禁止 HTTP 自动重试；未完成请求禁止 commit。protocol retry 按 11.10.14。
24. 不支持的能力必须显式 400，不得静默忽略。
25. Decode 外部 batch 固定 1；MTP verify 的 T 行属于单请求内部。该约束只描述 GPU batch，不代替 RequestGate 的请求级单并发。
26. metadata 缺失或不合法时直接报错。
27. 超出预算直接报错，不自动回退。
28. 图片只支持静态单帧 PNG/JPEG/WebP/BMP；GIF、APNG、animated WebP、动画图片均不支持。
29. 任意输入尺寸，限制单文件 10MB、解码后 40MP；输出必须是 768×768 RGB8。
30. 图片只允许 letterbox pad 到 768×768，padding 颜色 gray 127；禁止 crop/stretch。
31. EXIF Orientation 必须修正；alpha 合成到 gray 127。
32. 每张图片固定 576 个 `<|image_pad|>`，对应 vision encoder 的 24×24 输出；不得按输入尺寸改变 token 数。
33. mmproj 是独立视觉权重，不写入 SRS1；缺失 mmproj 时图片请求显式 400。
34. C++ raw API 接收 RGB8 图片并执行 vision encoder；Python frontend 只做格式解析/下载/解码/letterbox，不加载视觉模型。
35. image token 必须用 `<|image_pad|>`（248056）；`<|vision_start|>`/`<|vision_end|>` 必须由 tokenizer 识别为单 token。
36. 单请求最多 4 张离散静态图片；超过显式 400；GIF/APNG/animated WebP/视频不算离散图片。
37. 图片内容参与 session/image_hash 匹配；不同图片不得复用图片后的 prefix。
38. Tool-call 只使用固定 JSON 格式，不使用自由 XML：`{"name":...,"arguments":{...}}`。
39. Tool-call 约束只在 tool-call 生成阶段启用；普通文本阶段不启用 grammar mask。
40. Tool name 必须是请求声明集合中的 enum；arguments 必须匹配可编译的 JSON Schema 子集。
41. 不支持或无法编译的 schema 必须显式 400；禁止静默退回自由生成。
42. Grammar mask 不逐 token 扫描完整 248k vocab；必须使用 token trie、grammar state mask cache 和稀疏/位图两路采样。
43. Tool-call 约束阶段禁止开启 MTP；普通文本阶段 MTP 不受影响。
44. Tool-call 约束的 decode 开销目标 <5%；prefill 不受影响。
45. Pi 必须保持官方实现；不得 patch/fork/依赖自定义 extension；tool protocol retry 全在 Python frontend gateway。
46. X-Commit-Mode 默认 immediate；deferred 只由 gateway 的 tool attempt 0 显式启用。
47. deferred 必须同时带非空 X-Session-ID；commit 前不得改变 committed prefix。
48. tool attempt 0 用 session+deferred；retry 1/2 不带 session，retry 成功不 commit。
49. abort 必须恢复上一个 committed checkpoint；pending 必须有 TTL。
50. CLI 和普通 raw 请求保持 immediate commit，原有 prefix cache 不变。
51. 采样必须支持 temperature、top_p、top_k、min_p；top_k/min_p 默认关闭。
52. 所有 stochastic 采样必须走统一 multi-block cutoff/sample 流程；禁止单 CTA 扫完整 vocab；top_k=0 不得退化到单 CTA/full-sort；top_k>0 的 top_p/min_p/CDF 不得再次扫描完整 vocab。
53. MTP 与 top_k/min_p 同时启用时，draft 和 target 必须使用同一套截断并重新归一化；residual 不得再次截断。tool-call 约束阶段仍按第 43 条关闭 MTP。
54. Gateway 不得对重复 tool call 做硬拦截；重复调用必须交给工具实际执行，由工具结果决定成功或失败。禁止伪造 duplicate tool result。
55. v0.1 不实现 repetition_penalty、presence_penalty、frequency_penalty。
56. 重复 tool call 不得新增合成 tool result、duplicate 错误码或 telemetry；只保留工具的真实执行结果。
57. sampling 不新增 telemetry 字段；OpsLog schema 保持不变。
58. thinking 开启时，frontend 必须把 CoT 解析为 `reasoning_content` 并透传，禁止合并进 `content`。
59. CoT 必须原样进入下一轮 assistant history；thinking 模式和 reasoning_effort 对应的 prompt/history 序列化必须固定。
60. 同一 session 中途切换 thinking 模式或 reasoning_effort 不保证 prefix 命中；允许 full prefill，不得为此静默改写 history。
61. temperature=0 必须走独立 greedy argmax graph；不得包含 cuda_sample，不得启动 stochastic sampler。
62. greedy_sample 和 stochastic_sample 必须是两个独立 captured graph，不得共用 capture。
63. 所有 host/device 标量传输必须使用 pinned host buffer；禁止 pageable cudaMemcpy。
64. 纯文本 decode 不得在每个 token 生成前做阻塞式 D2H 同步；sampled token 在 device 上继续下一次 decode，D2H 仅用于 detokenize 并与 decode 重叠。tool/grammar 路径允许每 token 读取一个 token id，但不得传输完整 vocab/mask。
65. top_k>0 时，top_p/min_p/CDF 只允许在 top_k 候选缓冲区上计算；禁止第二次全词表 top_p radix。top_k=0 的全词表 top_p 必须 multi-block，禁止单 CTA/full-sort。
66. Runtime 必须在 SessionManager 之前提供全局 RequestGate；所有 completion（CLI/Server/raw/tool）必须持有 lease 才能进入 SessionManager。
67. RequestGate 的 lease 覆盖 open/prefill/decode/commit/abort/drain；deferred commit/abort 必须 finalize 同一 lease，不得重新 acquire；下一个请求只能在 lease 释放后开始。
68. RequestGate 等待必须支持 cancel 和 timeout；超时返回明确错误，不得绕过 gate。Scheduler 的 sample mailbox assert 必须保留，禁止在采样路径用 consume/reset 兜底。
69. 所有公开错误必须走统一 Error 对象和 render_http/render_sse/render_cli；禁止业务代码直接拼 status 或 502。
70. tool protocol 错误先走 GatewayRetry（同一 lease），重试耗尽返回 422 tool_truncated（retryable=false）；不得用 502，不得执行 partial call。
71. 首 delta 后只能发 SSE error，不得改 HTTP status、不得自动重试。
72. tool attempt 失败/abort 后必须保留 prompt-end prefix checkpoint；该 checkpoint 不得包含未提交 assistant，也不得变成 committed history。
73. retry 必须使用同一 session、same deferred 和 prefix-preserving suffix directive；retry 的 kv_hit_ratio 必须大于 0，否则视为实现失败。
74. 每次 attempt > 0 都必须重新构造 retry suffix：包含此前所有不同的失败 code，去重，不得只看最后一次 failure。提示必须用英文指出错误位置和修正方向。
75. Frontend 必须对外暴露统一 LoopGuard.check(session_id, messages) -> LoopDecision；调用 backend 前执行。
76. 重复 mutating 且 workspace 未变时，第一次只记录，第二次返回 422 no_progress；read/poll 使用 deadline，不得立即按重复拦截。
```

```text
--decode-batch

FP32 SIMT MoE
host activation ring
per-expert custom launch

per-matvec quantize
两套 Decode/MTP pre/post kernel
```

# 2. SRS1 v1

```text
magic       = SRS1
version     = 1
header_size = 4096
layers      = 48
experts     = 512
topk        = 10
expert_count= 24576
expert_offset = 4K aligned
role_count  = 3
role_offset[3]
role_bytes[3]
quant[48][3]
record_bytes = derived from role layout
```

`role` 顺序固定：

```text
0 gate
1 up
2 down
```

shape：

```text
gate: [expert_ff, width]
up:   [expert_ff, width]
down: [width, expert_ff]
```

`shared` expert 不在 expert record 里；  
它是 dense：

```text
ffn_gate_shexp
ffn_up_shexp
ffn_down_shexp
```

`quant` 每项：

```text
type = GGML quant type
```

**派生 Layout**

```text
record_bytes = align(role_offset[2] + role_bytes[2], 4K)
expert_bytes = record_bytes
quant_signature(layer) = (type[0], type[1], type[2])
```

`Layout` 是唯一来源：

```text
SlotPool
ExpertCache
StagingRing
TransferEngine
MMQ Product
D_total
graph capture
```

**约束**

```text
1. 只接受 version = 1。
2. 不接受 SRT3 或任何旧开发/测试 header。
3. record_bytes = align(role_offset[2] + role_bytes[2], 4K)。
4. quant 必须由 header 决定；禁止从 GGUF 猜。
5. 记录布局固定为 gate -> up -> down。
6. record_bytes 必须覆盖三个 role，且不得写死。
7. 不支持 header.record_size 或 layout.record_bytes 的固定常量比较。
8. 旧权重必须重新 pack 成 SRS1 v1。
9. gate/up 必须同 quant type、同 row layout；down 可以不同 type。
10. gate/up 合并顺序固定为 gate rows -> up rows。
11. gate/up direct 要求 role_offset[1] = role_offset[0] + role_bytes[0]；否则 gather 到 group buffer。
```

**读取**

```text
pread
O_DIRECT
4K 对齐
```

**禁止**

```text
mmap 作为正式 expert 数据层
page cache 当缓存
pread 后依赖 page cache 命中
旧版本 header 兼容
```

# 4. 内存预算

## 4.1 分配顺序

```text
1. 加载 dense、分配 Q8_0 KV、CUDA context
2. 若启用 vision：加载 mmproj、建 vision graph
3. 若启用 MTP：先 init DraftRunner（权重/KV/graphs）
4. tokenize，得到 max_prompt_tokens
5. tile = min(--chunk, context) = 1024
6. free = cudaMemGetInfo()
7. reserve = 1024 MiB
8. D_total = floor((free - reserve) / layout.record_bytes)
9. D_total 受 --gpu-expert-mib 上限
10. workspace_slots = ceil(Prefill workspace bytes / layout.record_bytes)
11. hidden_slots = ceil(hidden_bytes / layout.record_bytes)
12. hidden_slots 向上取整到 slot_chunk
13. D_prefill = D_total - workspace_slots - hidden_slots
14. D_decode = D_total
15. 锁定 D_total / D_prefill / D_decode / hidden_slots
```

MTP 必须在 D_total 之前分配。  
禁止先按无 MTP 的 D_total 分配、再加载 MTP、OOM 后回退。

hidden 不在 D_total 之前单独分配。  
hidden 从 SlotPool 尾部借用。

## 4.2 hidden

```text
hidden_tokens = max(max_prompt_tokens, 128)
hidden_bytes = hidden_tokens × width × hc × 4
```

约束：

```text
hidden 必须完整驻留 GPU
Prefill 期间只借一次
Prefill 后归还 SlotPool
跨层不 D2H/H2D
```

## 4.3 SlotPool

```text
slot 大小 = layout.record_bytes
slot count = D_total
```

地址稳定：

```text
slot address 在启动后不变
hidden 借用尾部 slot
MMQ direct 使用稳定地址
```

状态：

```text
Free
Reserved
Inflight
Resident
Active
Provisional
```

职责：

```text
key -> slot 映射
SLRU 淘汰
decode pin
hidden 尾部借用
MTP verify provisional 事务
```

禁止：

```text
slot 大小固定 1,769,472
跨量化复用固定 D_total
```

## 4.4 ExpertCache / TransferEngine

```text
ExpertCache 存 host record
record 大小 = layout.record_bytes
TransferEngine 搬 host -> slot
```

约束：

```text
O_DIRECT 读取
不依赖 page cache
copy batch 预取
compute 只等当前 batch copied event
```

## 4.5 StagingRing

```text
prefill_ring：1 GiB
decode_ring：8 MiB
route_slot：64 B pinned
```

边界：

```text
prefill_ring >= 64 × layout.record_bytes
ring records = floor(ring_bytes / layout.record_bytes)
```

禁止：

```text
用固定 1.6875 MiB 算 ring records
```

## 4.6 Vision

```text
mmproj Q8 约 589MB
vision activations 约 100MB
image embeddings 576 × 2560 × 4 = 5.9MB
固定预留约 1GB
```

约束：

```text
vision 权重必须在 D_total 之前加载
图片 token 的 KV 仍从现有 Q8_0 KV 分配
不为 vision 单独做 host cache
vision 失败不得回退纯文本
```

# 5. Prefill

## 5.1 外层循环

```text
for layer in 0..47:
  seen = 空
  for tile:
    before(tile)
    route
    GPU grouping
    counts D2H
    demand(new)
    for group of mmq_group experts:
      wait copied
      moe_experts
    sum_experts
    post
    原地写 hidden
  释放本层专家
```

固定：

```text
tile = min(--chunk, context) = 1024
mmq_group = 8–32，默认 16；实验上限 64
```

禁止：

```text
window = tile × N
整层 before 后再逐 tile 快照
Prefill CUDA Graph
```

## 5.2 每层步骤

```text
1. tile 做 attention/GDN/router
2. route ids 留 GPU
3. GPU grouping 生成 counts/starts/rows/dst
4. counts[512] D2H，仅用于 pin/demand/物理排序
5. seen 过滤，只 demand 本层未加载 expert
6. expert 按物理 offset 排序读取
7. 每 mmq_group 个 expert 一个 MMQ group
8. gate/up MMQ -> SwiGLU+Q8_1 -> down MMQ
9. 加权 scatter 到 expert_output
10. sum_experts
11. post 原地写 hidden
```

MTP prompt KV 不在这里构建；target Prefill 全部完成后，只用最后 `mtp_window` 的 final R 构建。

## 5.3 GPU grouping

```text
counts[512]
starts[513]
rows[token × topk]
dst[token × topk]
```

GPU 负责：

```text
counts
prefix sum -> starts
scatter rows
scatter dst
```

禁止：

```text
route ids D2H
host 计数
host 前缀和
host 拼 rows/dst
rows/dst H2D
```

host 只允许：

```text
counts[512] D2H
counts 同时累计 hot_count[layer][expert]
```

不允许 D2H：

```text
ids
rows
dst
route_weights
```

## 5.4 MoE op

`MoEKernel` 对外接口不变：

```text
moe_experts(
  gate_table, up_table, down_table,
  expert_input, starts, rows, dst,
  route_weights, expert_output,
  expert_begin, expert_end)
```

内部改为 MMQ：

```text
1. activation quantize 一次 -> Q8_1
2. expert union 按 mmq_group 一组
3. gate/up 一个 MMQ Product
4. SwiGLU + Q8_1 fused epilogue
5. down 一个 MMQ Product
6. weighted scatter / combine
```

约束：

```text
1. 不按 expert 单独 launch。
2. 不新增 MoE 模块或接口。
3. 不重建 Frame。
4. 不 dequant 到 FP16。
5. 每个 group 最多 64 个 expert；建议 8–32，默认 16。
```

## 5.5 gate/up MMQ

```text
gate/up 权重拼成一个矩阵
一次 MMQ Product
Q8_1 activation
FP32 输出 gate/up
```

`Product` 使用：

```text
type       = header quant type
w_rows     = 2 * expert_ff
w_cols     = width
bounds     = 每个 expert 的 token 行
expert_bytes = layout.record_bytes
tab = optional direct table
max_rows
```

热 expert：

```text
Product.tab = ExpertTable 指针表
不 gather
```

冷 expert：

```text
gather 到 group buffer
```

约束：

```text
1. gate/up 必须一个 product。
2. 每层 activation 只 quantize 一次。
3. 不按 expert 拆 gate/up。
4. 不 dequant 到 FP16。
5. MMQ 期间 pin slot，结束后 release。
```

## 5.6 down MMQ

```text
一次 MMQ Product
输入是 SwiGLU 产生的 Q8_1
输出 FP32
weighted scatter / combine
```

约束：

```text
1. down 不与 gate/up 合并成一个 MMQ。
2. down 不能等到下一层。
3. 不 dequant 到 FP16。
4. down 后处理尽量融合成一次 epilogue。
```

## 5.7 copy 流水

```text
demand 全部 missing
  -> copy group 0
  -> compute group 0 || copy group 1
  -> compute group 1 || copy group 2
```

约束：

```text
compute 只等当前 group 的 copied event
不等全部 expert
group 在 8–32，默认 16；实验上限 64
```

禁止：

```text
group > 64
compute 等全部 expert
per-expert copy launch
```

## 5.8 Kernel fusion（Prefill）

MMQ 路径的最大融合：

```text
gate/up 一个 Product
SwiGLU + Q8_1 一个 epilogue
down 一个 Product
weighted scatter/combine 一个 epilogue
```

明确不做：

```text
gate/up + SwiGLU + down 单 kernel
```

原因：

```text
down 的 K 维需要完整 hidden
MMQ gate/up 的 tile 分散在不同 CTA
```

### 11.1.1 RequestGate

Runtime 在 SessionManager 之前持有一个全局 RequestGate。

```text
RequestLease acquire(deadline, cancel)
finalize(lease, commit|abort)
release(lease)
```

状态：

```text
IDLE
ACTIVE_GENERATING
ACTIVE_DEFERRED
FINALIZING
```

规则：

```text
1. 同一 Runtime 同时只允许一个 RequestLease。
2. CLI、Server、raw completion 都必须先 acquire。
3. lease 覆盖 open -> prefill/decode -> commit/abort -> drain。
4. deferred completion 在生成结束后保持 ACTIVE_DEFERRED，
   直到同一个 request_id/commit_token 的 commit 或 abort。
5. commit/abort RPC 不重新 acquire；它 finalize 当前 active lease。
6. 下一个请求只能在 lease 释放并回到 IDLE 后开始。
7. 等待中的请求必须响应 cancel 和 deadline；排队超时返回 429 `queue_wait_timeout`，已有请求占用且立即拒绝返回 409 `model_busy`。
8. 不允许绕过 gate 直接进入 SessionManager/Engine/Scheduler。
9. SessionManager 不再负责请求排队，只负责 session 状态。
10. gate 的 deadline 只约束 admission 等待，不改变 Python 的 generation timeout/retry。
```

CLI 行为：

```text
CLI 每次 turn acquire 一个 lease
immediate commit 后 finalize
Ctrl+C -> cancel -> abort -> finalize
```

server 行为：

```text
HTTP completion acquire lease
immediate -> 生成结束 finalize
deferred  -> 生成结束保持 ACTIVE_DEFERRED
commit/abort RPC -> finalize
client disconnect -> abort -> finalize
```

### 11.1.2 deferred commit

```text
X-Session-ID 必须非空
成功后不 commit，只 stage
响应头 X-Commit-Token
```

```json
POST /v1/session/commit
{"session_id":"...","request_id":"...","commit_token":"..."}
```

```json
POST /v1/session/abort
{"session_id":"...","request_id":"...","commit_token":"..."}
```

约束：

```text
commit_token 绑定 session + request
同一个 token 重复 commit -> 幂等成功
已 commit 后 abort -> 409
abort 后 commit -> 409
pending 超过 30s -> 自动 abort
client disconnect -> abort pending
同一 session 同时只允许一个 pending
commit RPC 可重试同一 token；仍失败 -> abort + 500，不返回 Pi
commit/abort RPC 不 acquire 新 gate；必须 finalize 当前 ACTIVE_DEFERRED lease
finalize 完成 drain/cleanup 后才 release gate
deferred 期间下一个 completion 必须等待
```

### 11.1.3 统一错误接口

所有 C++/frontend/CLI 错误必须构造同一个对象：

```text
Error {
  code:       stable machine code
  type:       invalid_request_error | rate_limit_error | server_error | tool_error | conflict_error
  message:    human-readable
  phase:      admission | prefill | decode | tool_parse | commit | stream
  retryable:  bool, client retry only
  request_id: string
}
```

业务代码不得直接拼 status/message。

```text
make_error(code, phase, request_id, message) -> Error
render_http(error) -> status + headers + JSON
render_sse(error)  -> SSE error event
render_cli(error)  -> text + exit code
```

状态映射：

| code | status | retryable |
|---|---:|---|
| invalid_request | 400 | false |
| context_overflow | 400 | false |
| image_invalid | 400 | false |
| auth_failed | 401 | false |
| forbidden | 403 | false |
| not_found | 404 | false |
| model_busy | 409 | false |
| commit_conflict | 409 | false |
| tool_truncated | 422 | false |
| tool_protocol_error | 422 | false |
| structured_output_failed | 502 | false |
| queue_wait_timeout | 429 | true |
| engine_starting | 503 | true |
| engine_unavailable | 503 | true |
| upstream_disconnect | 502 | true |
| internal_error | 500 | false |

流式规则：

```text
首 delta 前：允许 render_http
首 delta 后：不得改 HTTP status，不得 502
            只能 render_sse，然后结束
任何自动重试只允许在首 delta 前
retryable=true 的公开错误也只表示首 delta 前可重试
```

tool truncation 的内部/外部语义：

```text
GatewayRetry 内部：
  ToolProtocolError{code=truncated, retryable=true}
  attempt 0/1/2 属于同一个 RequestGate lease
  失败 attempt abort，不 commit

重试耗尽：
  render_http(422 tool_truncated, retryable=false)
  不返回完整 tool_calls
  不执行 partial call
```

commit/abort：

```text
deferred tool call 必须先 commit 成功，才返回 tool_calls
commit 失败 -> abort pending -> 返回 commit 错误
不得先返回 tool_calls 再 commit 失败
```

断开：

```text
client disconnect -> cancel decode
未完成请求不得 commit session
abort pending -> drain/cleanup -> finalize RequestGate
```

## 11.4 Retry

只允许：


```text

```

HTTP 重试必须带同一个 `X-Request-ID`。

11.10.14 的 protocol retry 不是 HTTP 重试：  
它发生在 frontend 到 C++ 的一次模型请求失败、没有任何 tool 执行之后；frontend 丢弃失败输出并重新请求 C++。Pi 只看到最终一个完整响应。

后端已经接受请求后的 TTFT timeout 只结束当前 HTTP 等待，不取消 in-flight 任务、不重新 POST。相同 ID 重试继续等待原任务，完成后返回缓存结果。只有连接尚未建立，或后端明确声明未接受请求的 5xx，才允许重新 POST；首 delta 后禁止重试。客户端真正断开时取消后端，未完成请求不 commit。

## 11.10 Tool-call 约束

### 11.10.1 固定格式

只允许：

```text
<tool_call>
{"name":"bash","arguments":{"command":"pwd"}}
</tool_call>
```

约束路径允许连续多个 tool call block，最多 `max_calls`（默认 4，上限 8）。

```text
<tool_call>{...}</tool_call>
<tool_call>{...}</tool_call>
```

call 之间只允许空白；required/named 不允许在 call 之间插入自然语言。  
auto 允许在第一个 call 前、最后一个 call 后存在自然语言。  
不支持 XML function 语法和裸 JSON。

### 11.10.2 触发条件

```text
required
  -> 第一个 token 前 begin_tool_call()

named
  -> 第一个 token 前 begin_tool_call()

auto
  -> TEXT 状态开始
  -> observe(token) 检测 <tool_call>
  -> 命中后 begin_tool_call()
  -> 只约束 tool-call body
```

`auto` 允许普通文本；没有命中 `<tool_call>` 时全程不取 mask。  
命中后的 body 必须通过 grammar；仍不合法则报错，不回退自由生成。

多个 call：

```text
parallel_tool_calls=false -> max_calls 强制为 1
parallel_tool_calls=true  -> 1..max_calls
auto 可在 call 之间回到 TEXT；再次 observe 到 marker 后继续
```

required/named 在 call 之间只允许空白，不允许文本。

### 11.10.3 C++ raw 请求

```json
{
  "prompt": "...",
  "constraint": {
    "kind": "tool_call",
    "choice": "required",
    "max_calls": 4,
    "parallel_tool_calls": true,
    "tools": [
      {
        "name": "bash",
        "parameters": {
          "type": "object",
          "properties": {
            "command": {"type": "string"},
            "timeout": {"type": "number"}
          },
          "required": ["command"],
          "additionalProperties": false
        }
      }
    ]
  },
  "max_tokens": 256,
  "stream": false
}
```

`choice` 只允许：

```text
"required"
{"name":"bash"}
```

约束字段只由 Python frontend 生成，客户端不能传任意 GBNF。

OpenAI tool 映射：

```text
{type:"function", function:{name, description, parameters}}
  -> {name, description, parameters}
```

只保留 name/description/parameters；其余字段忽略。

`max_calls`：

```text
默认 4
范围 1..8
parallel_tool_calls=false -> 强制 1
超过范围 -> 400
```

### 11.10.4 Schema 子集

支持：

```text
object
array
string
number
integer
boolean
null
properties
required
additionalProperties: false
items
enum
const
```

`additionalProperties` 省略或 true 时，grammar 允许额外 key；这些 key 的语义仍由事后校验决定。  
`description` / `default` 忽略。

不支持：

```text
pattern
format
minimum / maximum
minLength / maxLength
dependentSchemas
anyOf / oneOf
本地或远程 $ref
```

不支持的 schema 在编译阶段显式 400，不静默退回自由生成。

### 11.10.5 GrammarVerifier

对外只暴露一个接口：

```text
GrammarVerifier
  configure(ToolConstraint, Tokenizer&) -> bool
  observe(token) -> bool          # auto trigger; true = 已进入 tool call
  begin_tool_call() -> bool       # required/named 直接启动
  finish_tool_call() -> bool      # </tool_call> 后回到 TEXT
  call_count() -> int
  active() -> bool
  mask() -> TokenMask
  advance(token) -> bool
  accepting() -> bool
  reset()
```

内部实现：

```text
JSON Schema
  -> DFA
  -> token trie
  -> state mask cache
```

DFA、trie、mask cache 都是 `GrammarVerifier` 内部细节，不单独暴露接口。

编译结果按 schema hash 缓存；同一组 tool schema 只编译一次。

### 11.10.5.1 按需启动

`GrammarVerifier` 默认 inactive。

只有当请求进入 constrained tool-call 阶段时，才调用：

```text
begin_tool_call()
```

规则：

```text
tool_choice=required / named
  -> decode 第一个 token 前 begin_tool_call()
  -> 全程约束

tool_choice=auto
  -> TEXT 状态
  -> 每个 emitted token 调 observe(token)
  -> 命中 <tool_call> 后 begin_tool_call()
  -> 只约束命中后的 tool-call body
  -> close 后 finish_tool_call() 回 TEXT
  -> 可再次 observe 下一个 call

普通文本回答
  -> 不开启约束

tool_choice=none
  -> 不开启约束
```

因此：

```text
tool call 阶段：active=true，mask 生效
普通文本阶段：active=false，无 mask 开销
```

### 11.10.5.2 Auto trigger

`auto` 的 TEXT 状态不产生 logits mask，只做 token 级 trigger 扫描：

```text
observe(token):
  把 token 的字节追加到 rolling buffer
  查找 <tool_call>
  未命中 -> false，继续自由生成
  命中   -> 把 marker 后的 suffix 交给 grammar body
             begin_tool_call()
             return true
```

触发后：

```text
<tool_call> 本身已经在 TEXT 状态生成，不再回溯
marker 后的 { ... } 由 GrammarVerifier 约束
</tool_call> 也必须由 grammar 接受
```

参考成熟引擎：

```text
XGrammar structural tags
llguidance grammar trigger
```

它们也是“先自由文本，命中结构标签后切换 grammar”，而不是整段文本都上 JSON grammar。

限制：

```text
<tool_call> 是保留 marker
普通文本里出现字面 <tool_call> 会被当成 tool call
v0.1 不做 escape；需要时由 prompt/parser 约定
```

多 call：

```text
auto:
  close -> finish_tool_call() -> TEXT
  再次命中 marker -> 下一个 call
  call_count 达到 max_calls -> 只允许文本或 EOS

required/named:
  close -> 若 call_count < max_calls，允许 WS + 下一个 call
  call_count 达到 max_calls -> 只允许 EOS
  不允许文本
```

call 之间不允许嵌套；每个 call 独立做 name/arguments grammar。

### 11.10.6 Decode mask

只有 `active()==true` 时：

```text
1. mask = GrammarVerifier.mask()
2. logits 不允许项置 -inf
3. accepting()==false 时 EOS 也必须 -inf
4. 正常 temperature/top_p/top_k/min_p
5. 采样
6. GrammarVerifier.advance(token)
7. 若 token 完成了 </tool_call>，GrammarVerifier.finish_tool_call()
```

`active()==false` 时：

```text
不取 mask
不扫描 vocab trie
不改 logits
```

但 auto 模式仍需：

```text
GrammarVerifier.observe(token)
```

它只扫最近 token 的字节是否命中 `<tool_call>`，不扫 248k vocab。  
命中后调用 `begin_tool_call()`，下一个 token 才开始取 mask。

这就是“按需启动”的性能边界。

禁止：

```text
每个 token 扫描完整 248k vocab
每 token 在 Python 侧计算 mask
每 token H2D 传 248KB 全 mask
```

必须：

```text
token trie
以 grammar state 为 key 的 bitset cache
稀疏 allowed list 与 bitset 双路径
mask 常驻 GPU，按 state 复用
```

### 11.10.7 性能预算

```text
tool-call decode 阶段 <5% 额外开销
prefill 不变
普通文本 decode 不受影响
```

工具调用通常只有 20–200 tokens；约束只在该阶段开启。

### 11.10.8 MTP

```text
tool-call 约束阶段关闭 MTP
auto 的 TEXT 阶段可继续 MTP
命中 marker 后关闭 MTP
普通文本阶段 MTP 不受影响
```

原因：

```text
draft token 可能被 grammar 拒绝
acceptance 下降
工具调用很短，关闭损失小
```

### 11.10.9 失败处理

```text
schema 不可编译 -> 400
grammar state 溢出 -> 500
mask cache 不足 -> 500
```

约束路径不得回退到自由生成。

### 11.10.10 严格 canonical，拒绝 legacy

正式格式只有：

```text
<tool_call>
{"name":"bash","arguments":{"command":"pwd"}}
</tool_call>
```

以下全部是 `legacy_format`：

```text
<function=bash>
<parameter=command>
<invoke>
</invoke>
</parameter>
```

行为：

```text
不解析
不转 JSON
不兼容
不执行
不静默忽略
```

没有 `strip`、`unwrap`、legacy fallback 或兼容开关。  
`auto` 的 TEXT 状态只识别 `<tool_call>`；出现 `<function=`、`<invoke>`、`</parameter>` 等 legacy token，整个 turn 判为 `legacy_format`，不当作普通文本。

裸 JSON 不是 tool call：auto 下可作为文本，required/named 下视为未产生合法 call。

### 11.10.11 ToolCallAssembler（Python frontend）

一次 assistant turn 必须先完整收集，再校验：

```text
push(delta) -> 累积
finish() -> 完整 turn
```

规则：

```text
1. 只接受 canonical <tool_call>...</tool_call>。
2. 必须完整闭合。
3. 必须解析 JSON。
4. 必须校验 tool name 和 arguments schema。
5. 必须检查 max_calls / parallel_tool_calls。
6. 任意一个 call 失败 -> 整批 reject。
7. 全部通过 -> 返回完整 calls。
8. content 为空且 calls 为空 -> 不是完整 assistant turn，禁止 commit。
9. tool request 的 finish_reason=length 且没有完整 call -> incomplete。
10. text-only 的 finish_reason=length 且 content 非空 -> 合法文本完成。
```

提交前判定顺序：

```text
assembler.finish(reason)
-> turn complete?
   yes -> settle(True) / commit
   no  -> settle(False) / abort -> ToolProtocolError
```

禁止先 `settle(True)` 再发现没有 assistant turn。

这是 **整批原子准入**：

```text
两个 call 中第二个 truncated
-> 第一个也不执行
-> 不产生 toolResult
-> 整轮 retry
```

Assembler 不执行工具，不重试，不提交 session。

tool_calls 在整批校验通过前不发给 Pi；文本 delta 可以流式发给 Pi。  
Pi 只看到完整、合法的 tool_calls。

### 11.10.12 Tool result 语义

```text
1. 每个 tool call 由 frontend 分配唯一 call_id。
2. 顺序保持模型输出顺序。
3. 每个 call 必须有且只有一个 tool result。
4. parallel_tool_calls=false 时只允许 1 个 call。
5. 部分失败按 call 回填 error；不得伪造成功。
6. call 未执行时也要回填 not_executed/error，不能静默丢失。
7. 所有 tool result 到齐前，不进入下一轮模型生成。
8. 工具执行失败不触发 protocol retry。
```

Pi 负责实际执行工具；Souris frontend 只负责：

```text
暂存完整 call
生成 call_id
回填 tool result
维护 tool_call_id 关联
```

`parallel_tool_calls=true` 时，执行可以并发，但结果必须按 call_id 全部回填。

整批原子只保证“准入前没有副作用”。  
全部 call 通过后，执行阶段的外部副作用无法回滚；执行失败按 call 回填 error。

### 11.10.13 大 tool call 与截断

Grammar 只能保证“正常结束的 call”合法，不能突破 `max_tokens`。

```text
输出上限在 JSON 中途到达
-> call 不完整
-> 不执行
-> 不伪造 result
-> GatewayRetry 自动重试，提示改用更小的 write/edit
-> 重试耗尽返回 422 tool_truncated，retryable=false
```

普通文本达到 max_tokens 不属于工具错误：

```text
200
finish_reason=length
正常返回已生成文本
不返回 tool_calls
```

要求：

```text
1. 单次 write 建议 <=80 行或 <=2KB 生成内容。
2. 大文件分多次创建/追加。
3. 截断后不得重复提交同一个大 call。
4. 截断不得静默成功。
```

这与 Strata 的 reply-cut nudge 同义；由 frontend gateway 实现，不修改 Pi。

### 11.10.14 ToolProtocolError 与 gateway retry

Parser 只抛错，不重试：

```text
ToolProtocolError {
  code: legacy_format | invalid_json | truncated |
        schema_invalid | unknown_tool | too_many_calls | invalid_response,
  retryable: true,          # gateway-internal only
  raw_snippet: string
}
```

`retryable=true` 只允许 GatewayRetry 使用；重试耗尽后公开错误必须是：

```text
422 tool_truncated
retryable=false
phase=tool_parse
```

Pi 不得把该公开错误当成可重试的上游故障。

以下错误不进入 protocol retry：

```text
tool_execution_error -> 返回 isError toolResult
context_overflow    -> compact / 写 PROGRESS
provider_error      -> 走现有 11.4 retry
side effect 已发生  -> 不自动重试
```

Frontend GatewayRetry 重试规则：

```text
attempt 0:
  session + deferred
  成功 -> assembler 校验 -> commit
  失败 -> abort pending，保留 prompt prefix checkpoint
  -> 下一个 attempt

attempt 1/2:
  same session + deferred
  prompt = 原 prompt + prefix-preserving suffix directive
  成功 -> abort pending -> 返回 Pi，不 commit
  失败 -> abort pending -> 下一个 / turn failed
```

关键约束：

```text
1. 所有 attempts 使用同一个 X-Session-ID。
2. 所有 attempts 使用 deferred。
3. retry directive 只能追加在 prompt 末尾，不得改变已有 prefix。
4. abort 只回滚未提交 assistant，不删除 prompt-end prefix checkpoint。
5. 只有 assembler 全部通过后才 commit attempt 0。
6. retry 成功后必须 abort pending，不 commit。
7. 下一轮 attempt 0 再补一次 full prompt + commit。
8. 整个 retry 序列仍在同一个 RequestGate lease。
```

每次失败必须：

```text
1. 丢弃 partial assistant
2. 丢弃 partial tool call
3. 丢弃 tool draft / stream draft
4. 不写 session
5. attempt 0 失败时 abort pending staged session
6. 不执行 tool
7. 保留原始 user message
8. 发一个新的模型请求
```

重试使用**临时 internal suffix directive**，不使用：

```text
外部用户 prompt
assistant prefill
外部 supervisor
user message 注入
```

指令内容：

```text
The previous assistant attempt was discarded before any tool ran.
It failed at: <exact error location>.
Required correction: <specific next-step direction>.

Think briefly about the exact failure and the smallest valid correction.
Then resume the same task and emit only complete canonical tool-call blocks:

<tool_call>{"name":"...","arguments":{...}}</tool_call>

Rules:
- Do not emit prose before or between tool calls.
- Do not use <function=...>, <invoke>, <parameter>, or </invoke>.
- Do not re-request a rejected call; fix the stated location first.
- For write/edit, use at most 40 lines or 1KB per call; split larger work.
- Continue from the files that already exist.
```

错误位置与修正方向：

| code | 必须指出的位置 | 修正方向 |
|---|---|---|
| truncated | tool arguments 被 max_tokens 截断 | 缩小 write/edit，拆分调用 |
| invalid_json | `<tool_call>` 内 JSON 非法 | 修正该 JSON，返回完整 block |
| legacy_format | tool 边界使用了 legacy XML | 改为 canonical `<tool_call>` |
| schema_invalid | arguments 不符合 schema | 修正字段名/类型/required |
| unknown_tool | tool name 未声明 | 只能使用声明的 tool |
| too_many_calls | 调用数超过 max_calls | 减少调用数 |
| invalid_response | 没有完整 assistant/tool turn | 返回完整 canonical call |

提示必须使用英文，先说明错误位置，再说明下一步方向；不要只写 “retry” 或 “invalid”。

每次 `attempt > 0` 都从**完整 failures 列表**重建 suffix：

```text
1. failures 按发生顺序保留
2. 相同 code 只保留一次
3. 每个 code 的提示都带位置和修正方向
4. 去重后的提示按顺序拼接
5. 不允许只看 failures[-1]
```

例如 `[truncated, invalid_response]` 必须同时包含：

```text
write 在参数中途被截断，必须拆小
上一次没有产生完整 assistant/tool turn
```

该 suffix directive：

```text
只在本次 retry request 存在
不写入 Pi session
不出现在用户消息
不进入下一轮上下文
```

GatewayRetry 的总耗时必须落在 Pi 的请求 timeout 内；  
必要时由 frontend 在启动配置中延长 backend timeout，但不能延长 Pi 的 HTTP 等待到无限。

retry 成功后的下一轮：

```text
Pi 发来包含 retry turn 的完整 history
attempt 0 带 session
C++ 从旧 committed prefix 读取缺失 turn
assembler 校验通过后 commit
```

这一轮可能 full prefill 一次；之后恢复 prefix 命中。

重试失败两次后：

```text
turn failed
返回明确错误
不无限循环
保留 PROGRESS.md / 已完成文件
```

### 11.10.15 Prefix cache 与 commit 矩阵

| 路径 | X-Session-ID | commit |
|---|---|---|
| CLI chat | 有 | immediate |
| text-only | 有 | immediate |
| tool attempt 0 | 有 | deferred |
| tool retry 1/2 | 无 | 不 commit |

约束：

```text
1. tool attempt 0 成功 -> commit -> 下一次 tool turn 命中 prefix。
2. tool attempt 0 失败 -> abort -> committed prefix 不变。
3. tool retry 成功 -> 返回 Pi，但不 commit。
4. retry 后下一轮 attempt 0 可补一次 full prefill 并 commit。
5. CLI / text-only 行为不变。
6. deferred 只允许 tool attempt 0，不允许普通请求启用。
```

### 11.10.16 重复 tool call

Gateway 不比较、不拦截、不改写重复 tool call。

规则：

```text
1. 同一个 assistant 输出中的调用都交给 assembler 校验。
2. 跨 turn 的相同 name + arguments 不再触发 duplicate。
3. 每次调用都交给工具执行，由真实 tool result 决定结果。
4. read/查询/轮询可以合法重复。
5. write 可以重复覆盖；edit 重复由工具报“旧文本不存在”。
6. bash 重复由工具返回真实结果，例如端口占用或命令错误。
7. 不生成 synthetic duplicate error、tool result 或 telemetry。
8. 不新增 duplicate retry 预算。
```

重复执行的风险由工具语义和工具结果承担，不由 gateway 猜测。

### 11.10.17 LoopGuard

Frontend 对外暴露一个接口：

```text
LoopGuard.check(session_id, messages) -> LoopDecision
```

在调用 backend 之前执行。它只解析当前 user turn，按 tool step 增量更新。

工具分类：

```text
read / ls / cat / grep / status -> read
write / edit                    -> write
bash / other                    -> unknown
```

规则：

```text
1. write/edit 成功但路径 hash 未变 -> 记录一次 no-op
2. 连续第二次 no-op -> 422 no_progress
3. write/edit 路径 hash 改变 -> 清除 no-op 计数
4. read/poll 相同 action+result -> 设置 poll deadline，deadline 前允许
5. poll deadline 到期 -> 422 poll_timeout
6. 新 user message -> 重置 turn 状态
```

错误：

```text
422 no_progress / poll_timeout
type=tool_error
phase=agent_loop
retryable=false
```

不注入模型提示，不依赖 Pi 的重复检测。

## 11.11 Sampling

### 11.11.1 参数

C++ raw 和 Python frontend 都支持：

```text
temperature
top_p
top_k
min_p
```

内部 sample_params 固定为：

```text
[temperature, top_p, top_k, min_p, random]
```

不新增采样接口。

默认：

```text
top_k = 0       # 关闭
min_p = 0       # 关闭
```

校验：

```text
temperature >= 0
0 < top_p <= 1
top_k 是 >= 0 的整数
0 <= min_p <= 1
不合法 -> 显式 400，不静默修正
```

语义：

```text
top_k > 0:
  只保留概率最高的 top_k 个 token

top_k = 0:
  不按数量截断

min_p > 0:
  保留概率 >= min_p * p_max 的 token
  p_max 是截断前的最大 token 概率

min_p = 0:
  不按 min_p 截断
```

`temperature = 0` 仍走 greedy，忽略 top_k/min_p/top_p。

### 11.11.2 应用顺序

```text
logits
-> grammar/tool mask（仅 tool-call 阶段）
-> temperature softmax
-> top_k
-> min_p
-> top_p
-> 归一化
-> sample
```

top_k/min_p 不得改变 grammar mask 的合法性；mask 仍然先于截断。

### 11.11.3 统一采样器

所有 `temperature > 0` 的请求走同一套 multi-block sampler，不再区分 top_k>0 / top_k=0 的快慢路径。

```text
Stage 0: softmax 统计
  multi-block max
  multi-block sum(exp)
  grid reduce

Stage 1: cutoff
  min_p > 0 -> p_max * min_p
  top_k > 0 -> radix count select 求第 k 大阈值
  top_k > 0 -> 把 k 个候选（id + weight）写入候选缓冲区
  top_k > 0 + top_p < 1 -> 只对候选缓冲区的 k 个值做 cumulative top_p
  top_k > 0 + min_p > 0 -> 只对候选缓冲区做 min_p
  top_k = 0 + top_p < 1 -> 才允许对完整 vocab 做 multi-block radix mass select
  final cutoff = max(启用的 cutoff)

Stage 2: sample
  top_k > 0 -> 只在候选缓冲区做 CDF/sample
  top_k = 0 -> 扫描 support
  求 support mass
  block-local CDF 前缀
  grid prefix reduce
  选中 block 内局部分段定位
  输出 token
```

约束：

```text
1. 任何 stochastic 请求都不得对完整 vocab 排序。
2. 不保留旧 argsort/CDF stochastic fallback。
3. top_k=0 只是跳过 top_k cutoff，仍走同一 Stage 0/1/2；
   不得进入单 CTA 或 full-sort 的慢分支。
4. top_p=1 只是跳过 top_p cutoff；min_p=0 只是跳过 min_p cutoff。
5. top_k>0 时，top_p 和 min_p 只允许在 top_k 候选缓冲区上计算；
   禁止再次对完整 vocab 做 top_p radix。
   top_k=0 时才允许完整 vocab 的 multi-block top_p radix；
   不得用固定 top_k=64 近似。
6. 只通过现有 sample_params 传递参数，不新增外部 API。
7. 采样流程不得改变 prefill。
8. 采样流程不得每 token 做 host 同步；内部 stage 可在同一 captured pipeline 内完成。
9. temperature=0 仍走独立 greedy argmax；greedy 不是 stochastic fallback。
10. 禁止单 CTA 扫描完整 vocab。
11. 禁止单 CTA 做多轮全词表 radix。
12. 248k vocab 下 Stage 0/1/2 必须由多个 CTA 并行完成；
    不允许 sample_kernel<<<1, 256>>> 这种实现。
13. top_k=0 与 top_k=20 必须使用同一套 multi-block Stage 0/1/2，
    不允许 top_k=0 走 else 全量慢分支。
14. top_k>0 的候选缓冲区必须保存 id + weight；
    top_p/min_p/CDF 不得再次扫描完整 vocab。
15. top_k=0 的 top_p 全词表 mass scan 是精确性所需，
    但仍必须 multi-block；不得单 CTA、不得 full sort。
```

### 11.11.4 MTP 统一

普通文本阶段 MTP 与 top_k/min_p 同时启用时：

```text
p_trunc = normalize(truncate(p, top_k, min_p, top_p))
q_trunc = normalize(truncate(q, top_k, min_p, top_p))
```

其中：

```text
p = target 分布
q = draft 分布
```

验证和 residual：

```text
residual = normalize(max(p_trunc - q_trunc, 0))
```

residual 采样时：

```text
top_k = 0
min_p = 0
top_p = 1
```

不得对 residual 再次截断。

draft 和 target 必须使用同一组 top_k/min_p/top_p 参数；residual 固定关闭截断。

tool-call 约束阶段仍按 11.10.8 关闭 MTP；该关闭优先于本节。

### 11.11.5 性能

```text
1. any stochastic sampling must not sort the full vocab.
2. sampling overhead must not exceed 5% of decode.
3. top_k=0 must not use single-CTA/full-sort; top_k>0 must not run a second full-vocab top_p/min_p/CDF scan.
4. MTP off/on must not change output correctness.
5. top_k/min_p defaults off, ordinary text behavior must not regress.
6. sampling must not reduce existing prefill metrics.
7. greedy_sample and stochastic_sample must be separate captured graphs.
8. greedy graph must contain only argmax; it must not contain cuda_sample.
9. stochastic graph must not be used for temperature=0.
10. 所有 host/device 标量传输必须使用 pinned host buffer；禁止 pageable cudaMemcpy。
11. 纯文本 decode 不得在每个 token 生成前做阻塞式 D2H 同步；
    sampled token 应在 device 上直接供下一次 decode 使用，
    pinned buffer 的 D2H 只用于 detokenize，并与下一次 decode 重叠。
12. tool-call / grammar 路径允许每 token 同步读取一个 token id，
    但仍禁止完整 vocab 或 mask 的 D2H。
```

### 11.11.6 非目标

```text
repetition_penalty
presence_penalty
frequency_penalty
文本 n-gram 重复检测
reasoning / thinking / CoT 重复检测
文件 hash no-progress
```

重复 tool call 不拦截；由工具真实执行结果决定，不靠采样惩罚。

## 11.12 CoT 暴露与缓存

CoT 只属于 Python frontend 的 chat 路径；C++ raw completion 仍只处理文本。

### 11.12.1 请求信号

```text
reasoning_effort = none | minimal | low | medium | high
```

规则：

```text
缺省或 "none" -> thinking off
minimal/low/medium/high -> thinking on
```

该字段是请求级参数，每个请求独立生效。  
Pi 是否发送由 Pi 决定；frontend 不强制开启。

### 11.12.2 生成 prompt

thinking off：

```text
<|im_start|>assistant
<think>

</think>

```

thinking on：

```text
<|im_start|>assistant
<think>
```

模型从 `<think>` 之后开始生成 reasoning，直到 `</think>`。

thinking on 时，system prompt 必须包含固定的 effort 指令：

```text
minimal -> 最短 reasoning
low     -> 简短 reasoning
medium  -> 中等 reasoning
high    -> 充分 reasoning
```

同一 effort 的指令 token 必须完全一致；effort 改变时允许 prompt 改变。  
effort 指令不写入 assistant history。

### 11.12.3 流式解析

thinking on 时，frontend 必须用状态机分离：

```text
<think> 之后，</think> 之前 -> reasoning_content
</think> 之后                 -> content
```

约束：

```text
1. reasoning_content 不得混入 content。
2. tool-call marker 只在 content 状态识别。
3. tool call 之前的 CoT 不得进入 ToolCallAssembler。
4. 模型重复输出开头的 <think> 时只剥离一次，不重复进入 content。
5. thinking on 但未在结束前出现 </think> 时，整轮视为不完整：
   不执行 tool
   不返回伪造 content
   按现有 protocol failure 处理
```

### 11.12.4 响应格式

SSE：

```json
{"delta":{"reasoning_content":"..."}}
{"delta":{"content":"..."}}
```

最终 message：

```json
{
  "role": "assistant",
  "reasoning_content": "...",
  "content": "..."
}
```

thinking off 时不产生 `reasoning_content` 字段。

Pi 可以忽略 `reasoning_content`，但 frontend 必须正确提供。

### 11.12.5 History 序列化

thinking on 的 assistant history 固定为：

```text
<|im_start|>assistant
<think>
{reasoning_content}
</think>

{content}
```

如果有 tool call，则：

```text
<|im_start|>assistant
<think>
{reasoning_content}
</think>

{content}
<tool_call>...</tool_call>
```

thinking off 固定为：

```text
<|im_start|>assistant
<think>

</think>

{content}
```

禁止：

```text
同一段 history 一轮有 think，一轮没有
把 reasoning_content 丢弃后再要求 prefix 命中 assistant 段
动态改写已有 assistant history
```

### 11.12.6 缓存约束

```text
1. reasoning_content 是 assistant token 的一部分。
2. 同一 effort 下 prompt 必须稳定，prefix 可复用。
3. effort 改变时允许 prompt 改变和 prefix miss；允许 full prefill。
4. effort 可逐请求调整，不要求整个 session 固定。
5. Pi 丢弃 reasoning_content 时，content 仍可返回，但 assistant 段不保证命中 prefix。
6. 不得为了缓存命中而忽略 effort，或伪造 reasoning_content。
```

### 11.12.7 Telemetry

```text
不新增 reasoning token 字段
不记录 reasoning 内容
不新增 sample 字段
OpsLog schema 不变
```

### 11.12.8 非目标

```text
CoT 重复检测
CoT 截断重写
CoT 内容评分
```

CoT 重复不触发 tool 错误，也不改变采样。

# 12. SessionManager / Prefix

## 12.1 Prefix

只缓存最后一个 session，不做 radix tree。

```text
PrefixCheckpoint:
  session_id
  length
  slot
  stamp
  images[]          # image_hash + token_start + token_count
```

checkpoint 只保存：

```text
GDN conv
GDN recurrent
PLE history
position
```

不保存：

```text
QSA K/V
QSA index
hidden
logits
```

匹配：

```text
best = 0
for cp:
  if cp.session_id == manager.active_id
     && cp.length <= prompt.size()
     && cp.length <= manager.tokens.size()
     && cp.images == request.images
     && prompt[0:cp.length] == manager.tokens[0:cp.length]:
       best = max(best, cp.length)
```

图片匹配：

```text
cp.images 必须与本次请求的 image_hash/顺序/位置完全一致
任意图片不同 -> 不命中
不能只比较 image_pad token
```

允许：

```text
cp.length == prompt.size() -> 从 length-1 恢复，重算最后一个 token
cp.length < prompt.size()  -> 恢复后 prefill suffix
```

未命中：

```text
清空 KV/index/GDN/PLE
清空 checkpoints
position=0
从头 prefill
```

执行：

```text
restore cp:
  GDN/PLE <- cp.slot
  position = cp.length - 1

suffix = prompt[cp.length-1:]
prefill(suffix, start=cp.length-1)
decode
```

KV/index：

```text
[0, cp.length) 继续用
[cp.length, ...) 旧 tail 不读
新 suffix 覆盖
不复制、不截断
```

checkpoint 创建：

```text
1. 每轮 assistant 生成结束
2. 每轮 prompt prefill 结束
3. 每 2048 token 可选
4. 最多 8 个；淘汰最老非 pinned
```

捕获/恢复：

```text
GPU D2D
不走 PCIe
只在请求边界发生
```

禁止：

```text
radix tree
跨 session 复用
非相邻 request 共享
复制 KV 到 checkpoint
用 checkpoint 回滚 KV
```

## 12.2 SessionManager

```text
open(session_id)
active_id()
tokens
position
checkpoints
match_prefix(tokens, images)
restore(length)
prefill(tokens, images, start)
decode(tokens)
commit(tokens)
stage_commit(request_id) -> commit_token
commit_staged(commit_token)
abort_staged(commit_token)
reset()
close()
```

约束：

```text
1. SessionManager 是唯一会话门面。
   checkpoint 的 GDN/PLE 对应 length-1，不缓存 hidden/logits；完整/扩展命中均重算旧边界的最后一个 token。
   prefix 命中后 DraftRunner.reset，仅用本次 suffix residual 重建 min(suffix_tokens,8192) 的 MTP KV。
2. 不设置 Session 类。
3. CliChat 和 Server 必须先 acquire Runtime RequestGate，再通过 SessionManager 执行会话操作。
4. SessionManager 不负责请求排队、admission 或 gate；这些只属于 RequestGate。
5. 未完成请求不得 commit。
6. deferred 只能 stage，不能改变 committed prefix。
7. commit_staged 把 pending 变成 committed；abort_staged 丢弃 pending。
8. 同一 session 同时只允许一个 pending；全局也只允许一个 active RequestLease。
9. pending 必须有 TTL；client disconnect 必须 abort 并 finalize lease。
10. CLI 继续使用 commit() 的 immediate 路径，不受 deferred 影响。
11. tool attempt 在 prefill 完成时捕获 prompt-end prefix checkpoint。
12. abort_staged 必须回滚 assistant/pending，但保留该 prompt-end prefix checkpoint 供同 session retry 复用。
13. 该 checkpoint 不包含失败 assistant，不改变 committed history，不暴露给 Pi。
14. 不同 prompt 不匹配时丢弃 scratch prefix；不得无限累积。
```

# 16. 验收

**Layout / 量化**

```text
1. 只接受 SRS1 v1；旧 header 拒绝。
2. quant 只接受 5.9 列出的类型。
3. record_bytes 由 role layout 动态派生，不写死。
4. D_total 用 layout.record_bytes 计算。
5. SlotPool/ExpertCache/StagingRing/TransferEngine/MMQ 使用同一个 Layout。
6. 不支持固定 record_bytes 或旧 record_size。
7. Prefill MoE 仍走 MoEKernel；内部 MMQ，不新增接口。
8. Layer/decode 走 GGML MMVQ/MMQ，不写 per-bit dequant。
9. 未知 quant type 或 record 布局启动报错。
10. 全部量化级别预留 type/Layout/dispatch/guard；v0.1 只验证 IQ2_XXS。
```

**Prefill MMQ**

```text
11. 每层 activation 只 quantize 一次。
12. mmq_group 建议 8–32，默认 16；实测 8/10/16/32/64 后固定。
13. copy 只等当前 group 的 copied event。
14. gate/up 一个 Product，down 一个 Product，不按 expert 单独 launch。
15. gate/up/down 的 type 和 expert_bytes 都来自 Layout。
16. 输出 top1 与参考路径一致。
17. 30K/32K prefill_moe_ms 和 prefill_ms 回退不超过 5%。
```

```text

T13. 一条 assistant 回复可生成 1..max_calls 个 call，全部可解析且顺序稳定。
T14. 多 call 中任意一个 protocol error -> 整批不执行，不产生 toolResult。
T15. 每个 assistant tool call 必须有 tool result 才能进入下一轮；execution error 按 call 回填。
T16. legacy `<function=>` / `<invoke>` / `</parameter>` 显式拒绝，不执行、不转换。
T17. 输出上限在 call 中途到达 -> 不执行、不伪造 result、不提交 partial assistant。
T18. Frontend gateway 内部 retry，最多 2 次；使用 prefix-preserving internal suffix directive，不改变原 prompt 前缀；Pi 官方代码不修改。
T19. 失败 attempt 不写入 session；已执行 tool 不因后续 protocol error 重复执行。
T20. 内部 suffix directive 不出现在用户消息、session 历史或下一轮上下文。
T21. 整批通过后执行阶段失败按 call_id 回填，不允许伪造成功。
T22. tool attempt 0 成功 -> commit；下一次 tool turn 的 kv_hit_ratio > 0。
T23. tool attempt 0 非法 -> abort；committed prefix 与 attempt 前一致。
T24. retry 1/2 使用同一 X-Session-ID + deferred，成功 abort pending，不 commit。
T25. CLI 和普通 raw 请求保持 immediate commit，行为与 deferred 引入前一致。
T26. pending TTL 到期、client disconnect、abort/commit 冲突均有明确错误。
T27. 相同 tool call 可以重复执行；gateway 不返回 duplicate 错误，也不伪造 tool result。
T28. 重复调用的成功/失败由工具真实结果决定；read 可重复，bash 重复可返回端口占用等真实错误。
T29. reasoning/thinking/CoT 重复不触发 tool 错误，不改变 CoT 内容或采样。
T30. 第一个长 completion 运行中时，第二个 completion 必须等待 RequestGate；不得进入 SessionManager/Scheduler。
T31. 第一个 completion 被 cancel 或 tool call truncated 后，第二个仍必须等待 abort/drain/finalize 完成，然后正常返回。
T32. deferred completion 的 commit/abort RPC finalize 同一 lease；期间第三个请求不得开始；未 finalize 不得释放 gate。
T33. 两个 Pi/两个客户端同时请求时，backend 必须串行执行；不得出现 sample mailbox assert、502 或同一 session 并发写。
T34. tool truncation 在 GatewayRetry 内最多 2 次；每次失败 attempt abort，不 commit，不执行 partial call。
T35. GatewayRetry 耗尽后返回 422 tool_truncated（retryable=false），不得返回 502。
T36. 首 delta 后发生错误只能发 SSE error，不得修改 HTTP status，不得自动重试。
T37. queue wait timeout 返回 429 queue_wait_timeout；已有请求占用并立即拒绝返回 409 model_busy。
T38. deferred commit 失败不得返回 tool_calls；必须 abort pending 后再返回错误。
T39. 空 assistant（无 content、无 tool_calls）不得 commit；必须 abort 并返回 422 tool_truncated/tool_protocol_error。
T40. write 在 max_tokens 中途截断时，GatewayRetry 自动重试；耗尽后 422，不出现 500 commit_failed。
T41. retry 使用同一 X-Session-ID；attempt 1/2 的 kv_hit_ratio > 0，prefill 只覆盖 suffix directive。
T42. retry 成功必须 abort pending，不 commit；committed history 不包含失败或 retry assistant。
T43. 失败 attempt 的 prompt-end prefix checkpoint 可被同 session retry 复用，但不会进入 committed prefix。
T44. 不同 session 或不同 prompt 不得复用该 scratch prefix；checkpoint 数量有界。
T45. attempt 1 的 suffix 包含 attempt 0 的失败原因；attempt 2 同时包含 attempt 0 和 attempt 1 的不同失败原因。
T46. suffix 对相同 code 去重，对每个不同 code 保留位置和修正方向；不得只看最后一次 failure。
T47. auto + parallel + max_calls=4 时，第 5 个 `<tool_call>` 前缀必须被 mask 排除，不得返回 internal grammar error。
T48. tool_request 路径的 MTP drafts 必须为 0；不得绕过 grammar mask。
T49. 连续 write 相同内容：第一次记录，第二次返回 422 no_progress；不得执行第三次。
T50. 重复 read/poll 在 deadline 前允许，deadline 后返回 422 poll_timeout；不得按重复次数立即拦截。
```
